# Git Workflow

## Overview

This document defines the Git workflow used in the Sirajum Monir project.

---

# Branch Strategy

## Main Branch

main

Contains stable production-ready code.

---

## Development Branch

develop

Used for integrating new features before merging into the main branch.

---

## Feature Branches

Examples

- feature-quran
- feature-hadith
- feature-dua
- feature-prayer
- feature-settings

---

## Bug Fix Branches

Examples

- bugfix-search
- bugfix-ui
- bugfix-prayer-time

---

# Commit Messages

Use short and descriptive commit messages.

Examples

- Add Quran module
- Fix search issue
- Improve prayer time UI
- Update localization
- Add documentation

---

# Commit Rules

- One logical change per commit.
- Commit frequently.
- Write clear commit messages.
- Avoid unnecessary commits.

---

# Pull Requests

Before merging:

- Review changes.
- Ensure the project builds successfully.
- Resolve conflicts.
- Verify documentation if required.

---

# Merge Strategy

Feature Branch

↓

Develop

↓

Main

Examples

---

# Best Practices

- Pull before pushing.
- Keep branches updated.
- Never commit sensitive information.
- Use meaningful branch names.
- Review code before merging.

- build/
- .dart_tool/# Git Workflow
