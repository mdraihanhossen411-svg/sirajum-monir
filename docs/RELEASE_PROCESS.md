# Release Process

## Overview

This document describes the release process for the Sirajum Monir application.

---

# Release Goals

- Deliver stable releases.
- Ensure application quality.
- Maintain version consistency.
- Provide a smooth user experience.

---

# Release Checklist

Before every release:

- All planned features completed.
- No critical bugs.
- All tests passed.
- Documentation updated.
- Version number updated.
- CHANGELOG updated.

---

# Versioning

The project follows Semantic Versioning.

Examples

- v1.0.0
- v1.1.0
- v1.2.0
- v2.0.0

---

# Build Process

Android

- Generate Release APK
- Generate Android App Bundle (AAB)

Future

- iOS Build
- Web Build

---

# Pre-Release Testing

Verify

- Splash Screen
- Navigation
- Quran
- Hadith
- Dua
- Prayer Time
- Qibla
- Tasbih
- Settings
- Localization
- Dark Theme
- Light Theme

---

# Performance Review

Check

- Startup time
- Memory usage
- App size
- Battery consumption

---

# Security Review

Verify

- No API keys exposed
- No debug logs
- Secure local storage
- Proper permissions

---

# Store Preparation

Prepare

- App Icon
- Feature Graphic
- Screenshots
- Privacy Policy
- App Description
- Release Notes

---

# Google Play Release

Steps

- Upload AAB
- Complete Store Listing
- Submit for Review
- Publish

---

# Post Release

- Monitor crashes
- Collect user feedback
- Fix reported issues
- Plan the next version

---

# Emergency Hotfix

If a critical issue is found:

- Create a hotfix branch.
- Fix the issue.
- Test thoroughly.
- Publish a patch release.

Example

v1.0.1

---

## Goal

Deliver stable, secure, and high-quality releases while maintaining a professional release workflow.
